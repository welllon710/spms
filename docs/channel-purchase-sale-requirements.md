# 采购和销售渠道模块需求

本文档整理 SPMS 中采购和销售渠道相关功能，用于新项目按接口替换方式复刻。

## 模块目标

通过供应商、客户、单价、单据，了解企业采购和销售的支出与收入。

模块范围：

```text
供应商
客户
采购价格
销售价格
采购单
销售单
入库联动
出库联动
```

## 涉及表

| 表 | 说明 |
| --- | --- |
| `supplier` | 供应商资料 |
| `customer` | 客户资料 |
| `purchase_price` | 供应商 + 物料 的采购单价 |
| `sale_price` | 客户 + 物料 的销售单价 |
| `purchase` | 采购单主表 |
| `purchase_detail` | 采购单明细 |
| `sale` | 销售单主表 |
| `sale_detail` | 销售单明细 |
| `material` | 物料资料，价格和单据明细都关联物料 |
| `input` | 入库单，采购完成后自动创建 |
| `input_detail` | 入库明细 |
| `output` | 出库单，销售审核后自动创建 |
| `output_detail` | 出库明细 |
| `coderule` | 供应商编码、客户编码、采购单号、销售单号自动生成 |
| `config` | 控制采购单、销售单是否自动审核 |

## 供应商

接口前缀：

```text
/supplier
```

### 字段

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| `name` | 供应商名称 | 必填 |
| `code` | 供应商编码 | 唯一，不传自动生成 |
| `phone` | 联系电话 | 手机号格式 |

### 功能

1. 新增供应商。
2. 修改供应商。
3. 查询供应商详情。
4. 分页查询供应商。
5. 支持按名称、编码搜索。
6. 原项目中 `SupplierController` 排除了删除接口，说明供应商不建议直接删除。

## 采购价格

接口前缀：

```text
/purchasePrice
```

### 字段

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| `material` | 物料 | 必填 |
| `supplier` | 供应商 | 必填 |
| `price` | 采购单价 | 必填 |

### 功能

1. 新增采购价格。
2. 修改采购价格。
3. 查询采购价格详情。
4. 分页查询采购价格。
5. 删除采购价格。
6. 查询指定物料和供应商的采购价格。

### 业务规则

1. 同一个 `供应商 + 物料` 只能配置一条采购价格。
2. 新增时如果已存在相同组合，则提示：

```text
物料 xxx 在供应商 xxx 下的采购价已存在!
```

3. 查询指定物料和供应商价格时，如果没有配置，则提示：

```text
没有查询到该物料在此供应商下提供的采购价格，请参考物料标准采购价填写。
```

### 特殊接口

```text
POST /purchasePrice/getByMaterialAndSupplier
```

请求中需要包含：

```text
material
supplier
```

返回对应采购价格。

## 采购单

接口前缀：

```text
/purchase
```

### 主表字段：`purchase`

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| `bill_code` | 采购单号 | 唯一，不传自动生成 |
| `reason` | 采购事由 | 必填，最多 80 字 |
| `total_price` | 总金额 | 只读，系统计算 |
| `total_real_price` | 实际金额 | 只读，系统计算 |
| `status` | 采购状态 | 字典值 |
| `reject_reason` | 驳回原因 | 驳回时必填 |

### 明细表字段：`purchase_detail`

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| `bill_id` | 采购单 ID | 必填 |
| `material_id` | 物料 ID | 必填 |
| `supplier_id` | 供应商 ID | 必填 |
| `quantity` | 采购数量 | 必填 |
| `price` | 采购单价 | 必填 |
| `finish_quantity` | 已入库数量 | 只读 |
| `is_finished` | 明细是否完成 | 只读 |

### 状态

| 值 | 状态 |
| --- | --- |
| `1` | 审核中 |
| `2` | 已驳回 |
| `3` | 采购中 |
| `4` | 入库中 |
| `5` | 已完成 |

### 功能

1. 新增采购单。
2. 修改采购单。
3. 查询采购单详情。
4. 分页查询采购单。
5. 审核采购单。
6. 驳回采购单。
7. 添加采购明细的完成数量。

### 业务规则

1. 新增采购单时必须带明细。
2. 保存采购明细后，自动计算采购总金额：

```text
totalPrice = sum(采购数量 * 采购单价)
```

3. 采购单审核通过后，状态变为 `采购中`。
4. _采购单驳回后，状态变为_ `已驳回`。
5. 已驳回的采购单允许重新编辑，编辑后回到 `审核中`。
6. 添加明细完成数量时，更新明细的 `finishQuantity`。
7. 当所有采购明细都完成后：
   - 采购单状态变为 `入库中`
   - 计算实际金额：

```text
totalRealPrice = sum(采购单价 * 已入库数量)
```

   - 自动创建采购入库单 `input`
   - 自动创建入库明细 `input_detail`

8. 如果完成状态是终态，则继续标记采购单为 `已完成`。原项目中采购单的明细完成状态是 `入库中`，最终完成状态是 `已完成`。

接口前缀：

```text
/sale
```

### 主表字段：`sale`

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| `bill_code` | 销售单号 | 唯一，不传自动生成 |
| `reason` | 销售说明 | 最多 80 字 |
| `total_price` | 总金额 | 只读，系统计算 |
| `status` | 销售状态 | 字典值 |
| `customer_id` | 客户 ID | 必填 |

### 明细表字段：`sale_detail`

| 字段 | 说明 | 规则 |

| `material_id` | 物料 ID | 必填 |
| `quantity` | 销售数量 | 必填 |
| `price` | 销售单价 | 必填 |
| `finish_quantity` | 已出库数量 | 只读 |
| `is_finished` | 明细是否完成 | 只读 |

### 状态

| 值 | 状态 |
| --- | --- |
| `1` | 审核中 |
| `2` | 已驳回 |
| `3` | 出库中 |
| `4` | 已完成 |

### 功能

1. 新增销售单。
2. 修改销售单。
3. 查询销售单详情。
4. 分页查询销售单。
5. 审核销售单。
6. 驳回销售单。
7. 添加销售明细的完成数量。

### 业务规则

1. 新增销售单时必须带明细。
2. 保存销售明细后，自动计算销售总金额：

```text
totalPrice = sum(销售数量 * 销售单价)
```

3. 销售单审核通过后，状态变为 `出库中`。
4. 销售单审核通过后自动创建销售出库单 `output`。
5. 根据销售明细自动创建出库明细 `output_detail`。
6. 销售单驳回后，状态变为 `已驳回`。
7. 已驳回的销售单允许重新编辑，编辑后回到 `审核中`。
8. 当所有销售明细都完成后，销售单状态变为 `已完成`。

## 单据通用接口

采购单和销售单都继承单据基类，因此都具有以下业务动作：

```text
POST /purchase/audit
POST /purchase/reject
POST /purchase/addFinish

POST /sale/audit
POST /sale/reject
POST /sale/addFinish
```

### 审核

请求：

```json
{
  "id": 1
}
```

逻辑：

1. 只有 `审核中` 状态允许审核。
2. 审核后进入对应的已审核状态。
3. 采购单审核后进入 `采购中`。
4. 销售单审核后进入 `出库中`，并创建出库单。

### 驳回

请求：

```json
{
  "id": 1,
  "rejectReason": "原因"
}
```

逻辑：

1. 只有 `审核中` 状态允许驳回。
2. 驳回后进入 `已驳回` 状态。
3. 记录驳回原因。

### 添加完成数量

请求：

```json
{
  "id": 1,
  "quantity": 10
}
```

逻辑：

1. `id` 是明细 ID，不是单据 ID。
2. `quantity` 是本次完成数量。
3. 系统累加明细的 `finishQuantity`。
4. 判断明细是否完成。
5. 如果所有明细都完成，则触发单据完成后置逻辑。

## 自动编码

该模块涉及以下自动编码：

| 业务 | 规则 |
| --- | --- |
| 供应商编码 | `SupplierCode` |
| 客户编码 | `CustomerCode` |
| 采购单号 | `PurchaseBillCode` |
| 销售单号 | `SaleBillCode` |

编码规则来自 `coderule` 表。

## 配置项

采购单、销售单是否自动审核由配置表控制：

| 配置 | 说明 |
| --- | --- |
| `PURCHASE_BILL_AUTO_AUDIT` | 采购单新增后是否自动审核 |
| `SALE_BILL_AUTO_AUDIT` | 销售单新增后是否自动审核 |

## 新项目复刻建议

第一阶段建议按以下顺序复刻：

1. `supplier`
2. `customer`
3. `purchase_price`
4. `sale_price`
5. `purchase` + `purchase_detail`
6. `sale` + `sale_detail`

第二阶段再联动：

1. 采购完成生成 `input` 和 `input_detail`
2. 销售审核生成 `output` 和 `output_detail`

如果新项目暂时不做 WMS，可先保留采购单和销售单自身状态流转，入库、出库联动后置实现。
